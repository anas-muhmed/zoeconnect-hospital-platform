# ADR-003: Builder / Renderer Separation

**Status:** Accepted (Frozen — Phase 1–6 roadmap approved 2026-07-05)

## Context

A form designer surface and a form-filling runtime surface have very different performance, security, and UX needs.

## Decision

The Builder (canvas) only ever edits a draft JSON Schema. The Renderer (runtime) only ever consumes a resolved, published JSON Schema through the six-stage rendering pipeline (ADR-007). Neither contains the other's logic; they share only the JSON Schema contract and the Component Registry (ADR-005).

## Consequences

Guarantees “what you designed is what clinicians get” structurally, not by convention. Enables independent Designer-API/Runtime-API scaling and RBAC (Phase 5A §1.6). Trade-off: any new feature must be considered on both sides of the boundary explicitly.
