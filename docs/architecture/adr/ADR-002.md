# ADR-002: Document Platform Abstraction (Form as One Document Type)

**Status:** Accepted (Frozen — Phase 1–6 roadmap approved 2026-07-05)

## Context

The original brief scoped a form-builder-only module. Phase 3 approval reframed this: the platform should generalize to any document type (Consent, Certificate, Prescription, Discharge Summary, etc.), with Forms as the first consumer.

## Decision

A generic Document Engine (Phase 4A §2) owns versioning, publishing, signatures, and PDF generation for any DocumentTypeDefinition. dynamic-forms registers 'form' as one Document Type and contains zero duplicated versioning/workflow/notification logic of its own.

## Consequences

Future Applications (Consent, Certificates, ...) are additive registrations, not redesigns. Trade-off: some generalization was built ahead of a second concrete document type actually existing — accepted deliberately (Phase 4A §10.1 risk) and scoped to data-shape/service boundaries only, not speculative UI.
