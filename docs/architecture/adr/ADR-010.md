# ADR-010: Component Deprecation Policy

**Status:** Accepted (Frozen — Phase 1–6 roadmap approved 2026-07-05)

## Context

Components will eventually need replacing (a better Signature control, a revised Table component) without breaking hospitals' years-old published forms.

## Decision

A four-state lifecycle — Active → Deprecated (hidden from palette, still renders, migration suggested) → optionally Retired (registry entry removed) — where Retired is only permitted once Analytics (Phase 4A §6) confirms zero production forms reference the component.

## Consequences

The Component Registry (ADR-005) can evolve indefinitely without ever breaking a published form. Trade-off: truly removing a component requires telemetry-backed proof of non-use, which is slower than “just delete it” but is the cost of the platform's durability guarantee.
