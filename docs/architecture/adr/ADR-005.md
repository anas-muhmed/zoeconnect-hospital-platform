# ADR-005: Component Registry

**Status:** Accepted (Frozen — Phase 1–6 roadmap approved 2026-07-05)

## Context

A form builder needs dozens of field/control types (basic, input, medical, table, layout) that must be addable over years without destabilizing the canvas or renderer.

## Decision

Every component type is a registered ComponentDefinition (id, displayName, DesignerComponent, RendererComponent, validate, serialize, defaultSchema, supported events/validations/bindings/themes, and — per Phase 5B — a propertySchema for automatic Inspector generation). Adding a component is a registration exercise; the canvas, renderer, and property panel never hardcode a per-type switch statement.

## Consequences

New components (including entire medical specialties) ship without touching core engine code. Trade-off: every component must fit the ComponentDefinition contract, including a genuinely-custom-control escape hatch (Phase 5B §2.3) for cases like the Body Diagram.
