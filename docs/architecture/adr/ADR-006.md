# ADR-006: Plugin SDK

**Status:** Accepted (Frozen — Phase 1–6 roadmap approved 2026-07-05)

## Context

Some component/template needs are specialty-specific (Dental, Burn, Cardiology) and shouldn't require core platform releases to add or update.

## Decision

A versioned FormBuilderPlugin manifest contract (components, templates, validators, toolbar/keyboard/theme/importer/exporter/context-menu contributions, and lifecycle hooks per Phase 5B §1.5) with an explicit sdkVersion compatibility check (Phase 4B §5) gating activation.

## Consequences

New specialties are installable, not core changes. Version skew between a plugin and the platform fails loudly (activation blocked with a specific reason) rather than corrupting the registry. Trade-off: v1 plugins remain trusted/first-party only — a full third-party sandboxing model is explicitly out of scope until designed (see Phase 6 §1.6 Marketplace, reserved not built).
