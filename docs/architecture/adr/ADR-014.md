# ADR-014: API Versioning and Compatibility Contract

**Status:** Accepted (Frozen — Phase 1–6 roadmap approved 2026-07-05)

## Context

REST endpoints will need to evolve; without an explicit contract, breaking changes risk silently breaking Designer or Runtime clients.

## Decision

Use Nest's existing global URI versioning (@Version(), already enabled platform-wide) for any breaking Forms endpoint change. Mutating endpoints support Idempotency-Key for safe retries. Draft/version mutations use explicit optimistic-concurrency checks (If-Match/expectedVersion) returning 409 with current state on conflict. Full OpenAPI/Swagger coverage is a documentation-discipline requirement, reusing the platform's existing Swagger setup.

## Consequences

Clients can rely on documented, versioned, retry-safe, conflict-transparent APIs. Trade-off: every mutating endpoint must be authored with idempotency/concurrency in mind from the start, not retrofitted after an incident.
