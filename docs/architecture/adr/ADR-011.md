# ADR-011: Multi-Branch/Department Inheritance Model

**Status:** Accepted (Frozen — Phase 1–6 roadmap approved 2026-07-05)

## Context

Hospital groups need branch- and department-specific variation (logo, footer, specific fields) without maintaining N full copies of every template.

## Decision

Global Template → Branch Override → Department Override, where an override is a JSON Patch (RFC 6902) delta plus simple metadata overrides — never a duplicated schema. A Resolver merges these at render/preview time and is cached, invalidated only on override publish. Branch/department identifiers are plain indexed strings (Oracle orgstructure id / HIS department code), matching the existing HDSP convention of not locally modeling HIS-sourced reference data as foreign-keyed tables.

## Consequences

One template, many branch variants, without maintenance multiplying by branch count. A branch override cannot silently remove a globally-required field (validated at override-publish time). Trade-off: override authoring is a delta/patch mental model, mitigated by always previewing the resolved form, never raw patch JSON, in the override editor.
