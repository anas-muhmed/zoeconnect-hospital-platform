# ADR-009: Explicit Schema Migration Strategy

**Status:** Accepted (Frozen — Phase 1–6 roadmap approved 2026-07-05)

## Context

FormSchema will evolve over years of production use; branching on schema version inside the Renderer (if (version==1)) accumulates unbounded technical debt.

## Decision

A SchemaMigrationEngine holds a registered chain of pure fromVersion→toVersion migration functions. The Resolver always upgrades a stored schema to the current version before the Renderer ever sees it. CI fails if the current schema version is bumped without a corresponding registered migration (Phase 6 §1.2, §3).

## Consequences

The Renderer never contains version-conditional logic. Every schema evolution has an explicit, tested, reversible-in-principle upgrade path. Trade-off: every breaking schema change requires writing and testing a migration as part of that change's definition of done — no shortcuts permitted.
